# 好YOU经验系统需求分析规格说明书

## 第1章 前言

### 1.1 项目背景

好YOU经验系统是一个面向职场经验分享与知识沉淀的平台。当前收入各岗位的核心经验、工作方法、典型案例分散在个人文档、聊天记录和口头传承中，缺乏统一的沉淀和检索机制，导致以下问题：

- 岗位认知标准不统一，不同团队对同一岗位的工作范围和要求理解存在差异。

### 1.2 项目目标

建设一套**以知识库为核心、覆盖从经验创作到审核发布全流程**的系统平台，目标：

| 目标维度     | 量化指标                   |
| :----------- | :------------------------- |
| 岗位认知覆盖 | 覆盖核心岗位的标准认知文档 |
| 员工入职赋能 | 新员工通过平台自学岗位认知 |

### 1.3 适用范围

| 范围       | 说明                                                         |
| :--------- | :----------------------------------------------------------- |
| **包含**   | 知识库文章的创建、审核、发布、浏览全流程；岗位认知文档管理；创作者申请与审核；文章检索 |
| **不包含** | 在线培训/考试功能（由现有培训系统承接）；视频/音频内容支持（二期规划）；知识库之间的自动关联推荐（二期规划） |

## 第2章 用户角色定义

本系统共涉及4类核心角色，各角色职责边界如下：

| 角色名称       | 角色描述                                     | 核心职责                                                     | 典型操作                             |
| :------------- | :------------------------------------------- | :----------------------------------------------------------- | :----------------------------------- |
| **读者**       | 浏览和查阅知识库内容的终端用户               | 查看知识库文章、按岗位检索认知文档、收藏/点赞                | 搜索、浏览、下载附件                 |
| **创作者**     | 负责撰写和提交知识库内容的用户（需申请成为） | 创建/编辑/提交知识库文章、查看审核进度、修改被驳回文章       | 提交文章、上传附件、查看审核状态     |
| **审核专员**   | 负责审核知识库内容质量与创作者资格的工作人员 | 查看待审核列表、审核通过/驳回、填写审核意见                  | 审批操作、查看详情、统计筛选         |
| **平台管理员** | 负责人员管理的后台管理人员                   | 管理创作者权限、管理岗位认知模板、配置审核流程、管理用户角色 | 角色分配、岗位增删改、创作者资质管理 |

**角色关系说明**：

text

```
[平台管理员] ──管理──> [创作者] ──提交──> [知识库文章] ──审核──> [审核专员]
      │                                                        │
      └──管理───────────────────────────────────────────────>[岗位认知模板]/[知识库文章] <─────查阅───── [读者]
```



- 读者可主动申请成为创作者，由平台管理员审批资质；
- 创作者提交的知识库文章由审核专员审核，审核通过后公开发布供读者查阅；
- 平台管理员负责维护岗位字典和认知模板框架，所有创作者和读者可查阅。

## 第3章 功能性需求

### 3.1 用户与账户模块

| 需求编号 | 需求描述                                                     |
| :------- | :----------------------------------------------------------- |
| FR-01    | 系统应支持用户通过手机号获取短信验证码完成注册               |
| FR-02    | 系统应支持用户使用手机号+密码方式登录                        |
| FR-03    | 系统应支持用户使用微信扫描二维码方式登录（扫码后手机端确认） |
| FR-04    | 系统应支持用户在有效期内自动登录                             |
| FR-05    | 系统应提供"忘记密码"功能，通过短信验证码验证后重置密码       |
| FR-06    | 系统应支持用户主动退出登录                                   |

### 3.2 创作者申请与管理模块

| 需求编号 | 需求描述                                                     |
| :------- | :----------------------------------------------------------- |
| FR-07    | 系统应允许普通读者提交"成为创作者"的申请，填写申请理由和资质说明 |
| FR-08    | 系统应将创作者申请推送至平台管理员进行审批                   |
| FR-09    | 系统应在创作者资质获批后，为申请者开通创作者角色权限         |
| FR-10    | 系统应支持平台管理员取消已有创作者的资格（需填写原因，留作审计） |

### 3.3 知识库管理模块

| 需求编号 | 需求描述                                                     |
| :------- | :----------------------------------------------------------- |
| FR-11    | 系统应允许创作者创建知识库文章，提交字段包括：**知识库名称、知识库类型、知识库摘要、显示类型、封面** |
| FR-12    | 系统 应允许创作者在提交前暂存  文章（草稿状态），支持后续继续编辑 |
| FR-13    | 系统应支持创作者上传附件（单个文件 ≤ 10MB，支持格式：PDF/JPG/PNG/DOCX） |
| FR-14    | 系统应在文章提交时校验必填字段（标题、岗位分类、正文）是否完整，不完整时给出明确提示并阻止提交 |
| FR-15    | 系统应在提交成功后生成唯一文章编号（格式：KB-YYYYMMDD-XXXX）并告知创作者 |
| FR-16    | 系统应允许创作者在文章被驳回后，根据驳回原因修改后重新提交   |
| FR-17    | 系统应允许创作者更新已发布文章，但更新后须重新进入审核流程（版本控制） |

### 3.4 审批流转模块

| 需求编号 | 需求描述                                                     |
| :------- | :----------------------------------------------------------- |
| FR-18    | 系统应在创作者提交文章后，自动将该文章推送至审核专员的待审核列表 |
| FR-19    | 系统应允许审核专员查看待审核文章的完整详情（含正文、附件预览） |
| FR-20    | 系统应允许审核专员选择"审核通过"或"审核驳回"，并填写审核意见（驳回时审核意见为必填） |
| FR-21    | 系统应在文章审核通过后，自动将文章状态变更为"已发布"，并对全体读者可见 |
| FR-22    | 系统应在文章被驳回时，将文章退回至创作者并附带驳回原因通知   |
| FR-23    | 系统应在创作者重新提交修改后的文章时，保留完整的审核历史记录 |

### 3.5 岗位认知管理模块

| 需求编号 | 需求描述                                                     |
| :------- | :----------------------------------------------------------- |
| FR-24    | 系统应提供"岗位认知"专区，按岗位分类展示标准认知文档（包含：岗位名称、岗位职责、任职要求、核心能力模型、典型工作场景） |
| FR-25    | 系统应支持平台管理员增删改查岗位认知条目                     |
| FR-26    | 系统应支持读者按岗位名称搜索和筛选认知文档                   |
| FR-27    | 系统应允许有权限的创作者投稿"岗位认知"类文章，审核通过后归入岗位认知专区 |

### 3.6 浏览与检索模块

| 需求编号 | 需求描述                                                     |
| :------- | :----------------------------------------------------------- |
| FR-28    | 系统应允许读者按**知识库类别（岗位）**、**知识库名称（关键词）**、**审核状态**筛选浏览已发布的文章列表 |
| FR-29    | 系统应提供全文搜索功能，支持对文章标题、正文、摘要进行关键词匹配 |
| FR-30    | 系统应展示文章详情页，包含标题、作者、岗位分类、发布时间、正文、附件下载入口 |
| FR-31    | 系统应展示该文章从提交到发布的全流程进度时间线（含各环节审核人、审核时间、审核结果） |

### 3.7 通知模块

| 需求编号 | 需求描述                                                     |
| :------- | :----------------------------------------------------------- |
| FR-32    | 系统应在以下事件发生时向相关用户发送站内消息通知：提交成功、审核通过、审核驳回 |
| FR-33    | 系统应支持用户在消息中心查看所有历史通知列表                 |
| FR-34    | 系统应允许用户标记通知为"已读"或"全部已读"                   |

## 第4章 非功能性需求

### 4.1可用性

| 需求编号 | 需求描述                                                     |
| :------- | :----------------------------------------------------------- |
| NFR-08   | 系统全年可用率须 ≥ 99.5%（即全年不可用时间累计不超过43.8小时） |
| NFR-09   | 系统须在工作日核心时段（9:00-18:00）发生异常时，在 ≤ 15分钟内通知运维人员 |
| NFR-10   | 系统须支持每日凌晨2:00-4:00进行计划内维护窗口                |

### 4.2 安全性

| 需求编号 | 需求描述                                                     |
| :------- | :----------------------------------------------------------- |
| NFR-11   | 用户密码须使用BCrypt或同等强度算法加密存储，任何人不得明文查看 |
| NFR-12   | 用户的手机号等个人敏感信息须在界面做脱敏显示（如：138****1234） |
| NFR-13   | 系统须满足《个人信息保护法》相关要求，支持用户注销账号后删除个人信息 |
| NFR-14   | 不同角色（读者/创作者/审核专员/管理员）须隔离数据访问权限，禁止越权操作 |

### 4.3 易用性

| 需求编号 | 需求描述                                                     |
| :------- | :----------------------------------------------------------- |
| NFR-16   | 所有表单必填字段须标注红色星号（*），提交时焦点自动定位到首个错误字段 |
| NFR-17   | 所有操作成功或失败后须在 ≤ 1.5秒内给出明确的视觉反馈提示     |
| NFR-18   | 文章列表须支持分页展示，每页默认显示15条                     |

### 4.4 数据与内容规范

| 需求编号 | 需求描述                                                   |
| :------- | :--------------------------------------------------------- |
| NFR-20   | 文章正文支持富文本编辑（标题、加粗、列表、引用、图片插入） |
| NFR-21   | 附件预览须支持常见格式（PDF/JPG/PNG/DOCX）在线打开         |
| NFR-22   | 系统保存创作者编辑中的草稿，防止内容意外丢失               |
